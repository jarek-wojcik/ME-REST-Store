# Data Model

All data is stored in a single BoltDB file. BoltDB organises data into **buckets** (analogous to tables). Each entity type gets its own bucket. Records are stored as JSON-encoded values keyed by their string ID.

---

## BoltDB Buckets

| Bucket | Key | Value | Defined in |
|---|---|---|---|
| `sfs` | arbitrary string | arbitrary string | `SFSWebserver.go` (legacy key/value store) |
| `teams` | team ID (hex string) | JSON-encoded `Team` | `teams.go` |

Future buckets (`bots`, `characters`, `weapons`, `powers`) follow the same pattern.

---

## Team

**File:** `teams.go`

```go
type Team struct {
    ID   string `json:"id"`
    Name string `json:"name"`
}
```

| Field | Type | Description |
|---|---|---|
| `ID` | `string` | 16-character random hex, generated by `crypto/rand` on creation |
| `Name` | `string` | User-defined display name, max 40 characters |

**Planned extension:**
```go
type Team struct {
    ID   string `json:"id"`
    Name string `json:"name"`
    Bots []Bot  `json:"bots,omitempty"`
}
```
BoltDB's JSON encoding handles the new field gracefully for existing records (it will be `nil`).

## ID Generation

All IDs are 16-character lowercase hex strings produced from 8 cryptographically random bytes:

```go
func newID() string {
    b := make([]byte, 8)
    _, _ = rand.Read(b)
    return fmt.Sprintf("%x", b)
}
```

This pattern is reused for every entity type.
